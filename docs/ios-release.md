# Releasing CyanBat on the App Store (iPhone and iPad)

This is the path from this repository to CyanBat on the App Store: what the iOS app is made of, what
had to change for it, what App Review will hold it to, and the steps to ship a release. Everything
up to signing is in the repository; signing, the App Store Connect record and the store listing
need an Apple Developer account and a Mac.

## What the iOS app is

- **`:ios`** (Kotlin) is the app proper: `MainViewController()` builds a Compose `UIViewController`
  that shows the shared menu or a run, exactly as `:desktop` and `:web` do. It is linked into the
  app as a static framework, `CyanBatGame`.
- **`:engine`'s `iosMain`** holds the platform pieces: `IosAudioDevice` (the app's one
  `AVAudioEngine`, its ambient audio session, and restarting it after a call or a route change),
  `IosLayeredMusic` (the shared `StemMixer` fed to a player node from a serial dispatch queue),
  `IosAudio` and `IosSound` (effects through `AVAudioPlayer`), `IosAssets` (the bundle's `assets/`
  folder) and `IosHaptics` (the Taptic Engine).
- **`iosApp/`** is the Xcode side, as an [XcodeGen](https://github.com/yonaskolb/XcodeGen) spec
  (`project.yml`) rather than a committed `.xcodeproj`: three small Swift files that put the Kotlin
  controller on screen and hide the status bar and home indicator, `Info.plist`, the privacy
  manifest, the asset catalog with the icon (`tools/generate_icons.py` writes it), and the
  localizations. Its build phase runs `./gradlew :ios:embedAndSignAppleFrameworkForXcode`, and the
  repository's `assets/` is copied into the bundle as a folder.
- **Persistence** is `NSUserDefaults` under the desktop's key names (`UserDefaultsStorage`), through
  the same stores the browser uses (`KeyValueStores` in `:game`).
- **Language** is iOS's per-app language (`IosLocale`), so the game's Settings and the system
  Settings app's language for CyanBat are one setting, as on Android 13 and later.
- **CI** (`ios` job) compiles `:ios`, runs the shared tests on the simulator, generates the Xcode
  project and builds the whole app for the simulator, unsigned.

## What was amiss, and what was done about it

| Finding | State |
|---|---|
| There was no iOS app at all: no host, no audio, assets, storage or haptics for iOS, no Xcode project, icon, `Info.plist` or privacy manifest. | Done on this branch. |
| A run could only be paused and quit with Back (Android) or Q/Esc (keyboards). An iPhone has neither, so a touch player had no way to pause a run or leave it short of dying. | The run now draws a pause button at the top right where the host asks for one (`CyanBatEnvironment.pauseButton`, on for iOS), and the pause screen a **Quit to menu** button. A finger put down on the pause button steers nothing (`TouchButton`, `PlayerInputSystem`). |
| The help dialog told iOS players to "swipe or press Back". | iOS has its own controls text (`dialog_help_controls_ios`), in all three languages. |
| Settings offered Vibration on an iPad, which has no Taptic Engine. | Offered on an iPhone only. |
| The shared menu does not pad itself for system insets. Edge to edge in landscape, its buttons would sit under the Dynamic Island and the home indicator. | The iOS host pads the menu to the safe area, over black, as the run's frame already is by its bars. |
| The menu's music would play on behind the home screen until iOS suspended the app. | Paused when the app resigns active and resumed on return, as Android's `MainActivity` does. |
| The privacy policy covered Android and the desktop only, and listed less than the game stores (no difficulty, clears, language or steering). | Rewritten for every platform, iOS and the browser included. |
| iPadOS 26 deprecates `UIRequiresFullScreen` and expects apps to take every orientation and any window size. | The iPad build takes all four orientations and resizes freely; the game fits its frame with bars, as in a desktop window. The iPhone build is landscape only, as on Android. |
| App Store Connect refuses builds whose binary uses "required reason" APIs it does not declare (ITMS-91053). Compose Multiplatform uses `stat`/`fstat` and `mach_absolute_time`, and the game uses `NSUserDefaults`. | `PrivacyInfo.xcprivacy` declares all three. |
| **Not yet verified on Apple hardware.** Everything iOS-specific compiles (Kotlin/Native cross-compilation), and CI builds the app, but nobody has run it. | Open: see *Testing before the first upload* below. |
| **Game controllers are not read on iOS** (nothing feeds `ControlHandler.onAxis`/`onButton` from Apple's GameController framework), and a pad does not rumble. A hardware keyboard on an iPad works. | Open. Do not claim controller support in the listing until it exists. |
| The death sound was an MP3 of unknown origin, the one piece of content neither generated by the repository's own tools nor hand-drawn for the game, and App Store Connect asks whether you have the rights to all content in the app. | Replaced by a generated one (`batDeath.wav`, from `generate_combat_sounds.py`), which also let the desktop drop its MP3 decoder. |
| **The repository has no license file.** | Open: not needed for the App Store, but worth choosing before the code is distributed further. |
| The iOS version is set in `iosApp/Configuration/Config.xcconfig`, apart from `gradle.properties`. | `archive.sh` stamps the tag's version, as the release workflow does for the other platforms. Keep the xcconfig in step in the "Stamp untagged builds" PR. |

## App Store compliance checklist

What App Review and App Store Connect will check, against the app as it is on this branch. The
references are to the [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/).

**Build requirements**
- [x] Built with Xcode 26 and the iOS 26 SDK, which App Store Connect has required of every upload
  since April 28, 2026. CI's `macos-latest` image and your Mac both need Xcode 26 or later.
- [x] Deployment target iOS 16 (any iPhone or iPad from 2017 on).
- [x] 64-bit only (`arm64`), no private APIs (2.5.1), no downloaded code (2.5.2): the whole game is
  in the binary, and its assets in the bundle.
- [x] `ITSAppUsesNonExemptEncryption` is `NO`: the game makes no network connection at all, so no
  export compliance documentation is needed.
- [x] Privacy manifest with every required reason API the binary uses. After the first upload,
  watch for an ITMS-91053 email: if one comes, add what it names. JetBrains' required reason
  finder lists a framework's uses ahead of time:
  [Kotlin's privacy manifest guidance](https://kotlinlang.org/docs/multiplatform/multiplatform-privacy-manifest.html).
- [x] App icon: one 1024×1024 opaque PNG, no transparency.
- [x] iPad: every orientation and resizable windows (no `UIRequiresFullScreen`).

**Design and behavior (4.0, 2.1)**
- [x] No Exit button: an iOS app must not quit itself (the main screen's Exit is hidden, as in the
  browser).
- [x] A visible way to pause and leave a run (the pause button and Quit to menu).
- [x] Content kept inside the safe area: the menu by insets, the game by its bars. In the
  **Stretch to fit screen** display mode the frame fills the screen and the HUD's corners can sit
  under the Dynamic Island; that is the player's own choice, and the default (ambient bars) is
  safe.
- [x] The status bar hidden, the home indicator auto-hidden, and edge swipes deferred, so a
  steering finger does not throw the player out of a run.
- [x] Audio respects the silent switch and mixes with the player's own music (ambient session).
- [ ] Runs well on an older device. Check on the oldest iPhone you can get, with the cave's
  lighting on screen.

**Privacy (5.1)**
- [x] Privacy policy at a public URL: `PRIVACY_POLICY.md` on GitHub,
  `https://github.com/msmiech/cyanbat/blob/main/PRIVACY_POLICY.md`.
- [x] App Privacy ("nutrition label") in App Store Connect: **Data Not Collected**. No tracking,
  so no App Tracking Transparency prompt and no tracking domains.
- [x] No account, so no sign-in or account deletion requirements (4.8, 5.1.1(v)).

**Metadata (2.3)**
- [ ] Screenshots of the iOS app itself, not of Android, the desktop or the README's GIF.
  Required sets: **iPhone 6.9"** (2868×1320 in landscape) and **iPad 13"** (2752×2064 in
  landscape). The simulator's File → Save Screen (⌘S) gives the exact sizes.
- [ ] Keep other games' names out of the name, subtitle, keywords and description (2.3.7): the
  README's mention of what inspired the game must not go into the listing.
- [ ] Do not mention Android, the desktop or the browser in the listing (2.3.10).
- [ ] Do not claim controller support until the GameController framework is wired up.

**Content and rating**
- [ ] Answer the age rating questionnaire for cartoon or fantasy violence: the bat shoots creatures
  constantly, with no blood or gore. Apple assigns the rating from the answers (4+, 9+, 13+, 16+
  or 18+); this is likely to come out at 9+.
- [x] Content rights: the music, the art and every sound are generated by the repository's own
  tools, or hand-drawn for the game.
- [x] No in-app purchases, ads or links to outside payment (3.1).

## Steps to release

### 1. One-time setup

1. **Join the Apple Developer Program** (99 USD a year) as an individual or an organization. The
   seller name on the store is the account's legal name.
2. **On the Mac:** install Xcode 26 or later from the App Store, open it once to install its
   components, then:
   ```bash
   brew install xcodegen
   ```
   A JDK must be on the `PATH` for Xcode's build phase to start Gradle (`brew install openjdk@21`
   or any JDK from 17 up: Gradle provisions JDK 25 for the build itself, as on the other
   platforms). Xcode's build phases do not read your shell profile, so if Gradle cannot find Java
   from Xcode, set `JAVA_HOME` in `~/.zshenv`, or start Xcode from a terminal with `open -a Xcode`.
3. **Sign Xcode in to the developer account** (Xcode → Settings → Accounts) and note the team id
   (Membership details on developer.apple.com). Put it in `iosApp/Configuration/Local.xcconfig`,
   which git ignores:
   ```
   DEVELOPMENT_TEAM = ABCDE12345
   ```
4. **Register the bundle id** `at.smiech.cyanbat` (Certificates, Identifiers & Profiles →
   Identifiers → App IDs). No capabilities are needed. Automatic signing would register it on
   first build too.
5. **Create the app in App Store Connect** (Apps → + → New App): platform iOS, name *CyanBat* (if
   it is taken, a subtitle-like suffix such as *CyanBat: Night Flight* will do), primary language
   English (U.S.), bundle id `at.smiech.cyanbat`, any SKU (`cyanbat`), full access.
6. **Agreements, tax and banking:** accept the Free Apps agreement under Business. Nothing else is
   needed for a free app.
7. **EU trader status** (Digital Services Act), under Business: declare whether you are a trader.
   A trader's address, phone and email are shown on the EU store page; without a declaration the
   app is not offered in the EU.

### 2. Build and try it

```bash
cd iosApp
xcodegen generate
open CyanBat.xcodeproj
```

Pick an iPhone simulator and run (⌘R). The first build compiles the Kotlin framework and takes
several minutes; later ones are incremental. Then run it on a real iPhone and a real iPad
(connected by cable, Developer Mode on).

#### Testing before the first upload

None of this could be tried without a Mac, so all of it needs a look:

- **Sound:** the menu's loop, a stage's layered music building with the combo, the muffle under the
  level-up dialog, effects, the fanfare and the game over's track. Listen for crackles: if the
  music stutters, raise `IosLayeredMusic.CHUNKS`. Also: the silent switch silences the game; a
  phone call, Siri, or unplugging headphones mid-run, then coming back; Music or a podcast playing
  alongside.
- **Pausing:** the pause button pauses; a tap resumes; *Quit to menu* leaves and keeps the
  highscore. Going to the home screen mid-run pauses the run and the menu's music.
- **Touch:** dragging the bat, the stick (Settings → On-screen stick), a finger landing on the pause
  button while another steers. Edge swipes do not leave the app on the first swipe.
- **Layout:** the menu clear of the Dynamic Island in both landscape orientations; every display
  mode; an iPad in portrait, in Split View and in a resized Stage Manager window.
- **iPad keyboard:** arrows/WASD fly, Q pauses, the menu's cursor keys.
- **Language:** Settings → Language switches the menu at once; the system Settings app → CyanBat →
  Language shows the same choice.
- **Persistence:** highscores, unlocks, clears and settings survive quitting the app from the app
  switcher.
- **Performance:** 60 fps (120 on a ProMotion screen) through the cave's lighting and the endless
  stage's storms on the oldest device at hand. Xcode's Debug navigator shows the frame rate.

### 3. Archive and upload

From the repository, on the Mac, for version 3.5:

```bash
iosApp/archive.sh 3.5
```

It generates the project, archives a Release build stamped 3.5.0 (build 30500), signs it for the
App Store and uploads it. Equivalent by hand: Product → Archive in Xcode, then Distribute App →
App Store Connect → Upload. Each upload of one version needs a higher build number: pass it as the
second argument (`iosApp/archive.sh 3.5 30501`).

The upload appears under TestFlight after a few minutes of processing.

### 4. TestFlight

1. Add yourself (and anyone else) as an internal tester; internal builds need no review.
2. Install through the TestFlight app on an iPhone and an iPad, and run the checks above against
   the build Apple will review.
3. Watch the account's email for upload warnings (ITMS-91053 and the like) and fix them before
   submitting.

### 5. The store listing (App Store Connect → the app → the version)

- **Name** *CyanBat*, **subtitle** (30 characters), for instance *Pixel-art night shooter*.
- **Description, keywords, promotional text**, in English, and in German and Polish under
  localizations, since the game speaks both. No other games' names (2.3.7).
- **Screenshots:** iPhone 6.9" and iPad 13", landscape, three to ten each. A run in each stage, the
  stage select and a level-up offer show the game best. An app preview video is optional.
- **Category:** Games, with *Action* and *Arcade* as the game's subcategories.
- **Support URL:** `https://github.com/msmiech/cyanbat/issues`. **Privacy policy URL** as above.
- **Copyright:** `2026 Martin Śmiech`.
- **Age rating:** the questionnaire, as above.
- **App Privacy:** Data Not Collected.
- **Pricing:** free, in all territories (or as chosen).
- **Build:** pick the TestFlight build.
- **App Review information:** no sign-in is needed. A note helps the reviewer, for instance:
  *"Drag the bat, or choose the on-screen stick in Settings. The button at the top right pauses; the
  pause screen leads back to the menu. Later stages unlock as earlier ones are cleared."*

### 6. Submit, and release

Add for Review → Submit. Review takes a day or two. Choose beforehand whether an approved version
goes out at once, on a date, or when you press release, and whether as a phased release over
seven days (only for updates). If it is rejected, the reason is in App Store Connect's Resolution
Center; answer there or fix and upload a new build.

### 7. Every later release

1. Tag as usual (`git tag 3.6 && git push origin 3.6`) for the other platforms.
2. `iosApp/archive.sh 3.6` on the Mac, from the tagged commit.
3. In App Store Connect, + Version → 3.6, pick the build, write "What's New", submit.
4. Bump `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` in `iosApp/Configuration/Config.xcconfig`
   in the "Stamp untagged builds" PR, next to `cyanbat.version`.

## The unsigned IPA on GitHub releases

The Release workflow's `ios` job builds the app for devices, unsigned, with `iosApp/build_ipa.sh`,
and attaches it to the GitHub release as `cyanBat-release-X.Y-ios-arm64.ipa`, beside the APK and the
desktop installers. It is for sideloading, not the App Store: AltStore, SideStore or Sideloadly sign
it with the player's own Apple ID as they install it (a free account's signature lasts seven days).
Nothing in it differs from the App Store build but the signature.

## Later: uploading from CI

The release workflow could upload too, from a `macos-latest` job running `iosApp/archive.sh` with
the tag. It would need an App Store Connect API key (Users and Access → Integrations, role App
Manager) as `ASC_KEY_ID`, `ASC_ISSUER_ID` and the `.p8` key base64-encoded into a secret, written
to a file whose path goes in `ASC_KEY_PATH`, which `archive.sh` passes to `xcodebuild` for signing
and for the upload; and `DEVELOPMENT_TEAM` written into `Local.xcconfig`. With an API key,
`-allowProvisioningUpdates` creates the distribution certificate and profile itself. It is left
until a first release has been made by hand, so that the steps it automates are known to work.
